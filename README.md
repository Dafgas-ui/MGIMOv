# MGIMOv — цифровой деканат, конкурсная версия RC4

Неофициальный самостоятельный проект. Все учебные данные синтетические.
Student получает собственные расписание, зачётку, БРС, учебные работы,
посещаемость, сроки, обращения, документы и уведомления. Staff работает
в пределах серверных назначений и полномочий, а не клиентской роли.
Стек: Python/FastAPI, SQLite, HTML/CSS/JavaScript ES modules, один origin.

## Реализованный объём

- Вход/выход, серверные сессии, Student/Staff, Origin/CSRF и изоляция данных.
- Расписание: день/неделя, переносы, отмены, история, редактирование Staff.
- БРС: опубликованные версии, пересдачи, исправления с аудитом; аттестации,
  комиссии, задолженности и электронная зачётка. Coursework не меняет её автоматически.
- Coursework lab/test/practice: черновик, публикация, получатели, текстовая и
  очная сдача, проверка, доработка, повторная сдача, история, явная публикация в БРС.
- Материалы/вложения: TXT/MD UTF-8, до двух по 64 КиБ; содержимое в SQLite,
  скачивание по серверным правам. PDF/DOCX и внешнее хранилище не реализованы.
- Посещаемость конкретного занятия, подтверждаемый состав и история исправлений.
  Пустой/неоднозначный состав запрещён; баллы БРС автоматически не начисляются.
- Прогноз из существующего серверного расчёта, отдельный от официальной оценки;
  прогресс с reduced motion. Калькулятора «что будет, если» нет.
- Учебные сроки: отдельные Student-источники, серверное время и бюджет всей
  загрузки 5 с. Это не атомарный снимок; обновление 30 с и при lifecycle-событиях.
  Во время остановки JavaScript интерфейс изменить невозможно.
- Встроенные уведомления о существующих событиях; push и полный набор
  напоминаний Coursework/посещаемости не реализованы.

## Локальный запуск

Проверенная среда разработки: Windows, Python 3.13, Node.js 24, Google Chrome.
Точные Python-зависимости закреплены в requirements*.txt и constraints.txt.
Linux/systemd/Nginx и текущий VPS для нового RC4 — NOT VERIFIED.
База обязательно находится внутри физического checkout проекта.
.env не читается. Startup не создаёт БД, не запускает миграции и seed.

На Windows checkout должен лежать в проверенной приватной области профиля
пользователя. При небезопасных правах родителя seed откажет. Не исправляйте
права существующей C:\Projects или .tmp ради запуска. Для подготовки приватной
копии из доверенного исходного checkout можно использовать:

```powershell
$private = & python -B -c "from pathlib import Path; from backend.commands.contest_demo_permissions import PrivateDemoDirectory; print(PrivateDemoDirectory(Path.home()).path)"
if ($LASTEXITCODE -ne 0 -or -not $private) { throw 'Private directory unavailable' }
$files = @(git ls-files --cached -- backend frontend tests requirements.txt requirements-test.txt constraints.txt package.json README.md RELEASE.md | Sort-Object -Unique)
if ($LASTEXITCODE -ne 0 -or -not $files) { throw 'Source inventory unavailable' }
foreach ($file in $files) { $target = Join-Path $private $file; [IO.Directory]::CreateDirectory((Split-Path -Parent $target)) | Out-Null; Copy-Item -LiteralPath $file -Destination $target -ErrorAction Stop }
Set-Location -LiteralPath $private
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -B -m backend.commands.seed_contest_demo --confirm-demo
```

Вводятся три НОВЫХ разных пароля: s01, s02, t01. Не записывать в Git или логи.
Seed сам создаёт новую SQLite и все 25 миграций, выводит DEMO_DB. Не выполнять
init перед этим seed. Повторный запуск создаёт другой экземпляр без дублей
в первой базе. Всего 20 аккаунтов; остальные 17 получают случайные пароли,
которые этот seed не выдаёт. Для полного набора доступов нужен отдельный
seed_attestations и согласованная подготовка Coursework, не смешение баз.

```powershell
$env:MGIMOV_DB_PATH = Read-Host 'Paste the DEMO_DB path printed by seed'
$env:MGIMOV_ORIGIN = 'http://127.0.0.1:8030'
.\.venv\Scripts\python.exe -B -m backend.commands.diagnose --db "$env:MGIMOV_DB_PATH"
.\.venv\Scripts\python.exe -B -m uvicorn backend.app:app --host 127.0.0.1 --port 8030 --no-proxy-headers
```

Открыть http://127.0.0.1:8030/. Остановить собственный сервер Ctrl+C.
Для другого порта одновременно изменить origin и --port. Не использовать file://.
Политика прав и генерации на POSIX требует отдельного Linux-прогона.
У demo назначения преподавателя действуют 7 дней, сроки Coursework — 2 дня:
перед показом проверить даты и доступ, а не менять часы ОС.

## Проверки и доказательства

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-test.txt
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -q
npm test
```

Полный Python-набор с ACL требует приватного checkout. Все тестовые SQLite
временные; рабочую базу не подключать. Браузерный набор требует Chrome,
Playwright Test из tests/browser и для части RC3.1-сценариев — локальную
синтетическую SQLite Astra и парный Windows DPAPI. Они не входят в Git/ZIP.
Команда из исходного checkout: npm --prefix tests/browser test.
Чистый клон не является самодостаточной фикстурой для всего Chrome-набора.
Последние результаты Sol: полная Python 225/225 на предыдущей серверной ревизии;
для финальной клиентской доработки — Python целевые 2/2, JS 105/105, Chrome 22/22
после повторного прогона. Первоначальный RU/EN timeout имеет неустановленную
причину. Luna: ACCEPT WITH CONDITIONS; это не разрешение публичного выпуска.

## Успеваемость V5

Раздел сохранён для ссылок из архитектуры. Текущая сессия определяется
серверным московским днём. Прогресс — доля успешно завершённых обязательных
неотменённых испытаний текущего семестра, каждое считается один раз;
нет данных — percent=null, не выдуманные 100%. Пересдачи не увеличивают
знаменатель, история сохраняется. Исторические долги показываются отдельно.
Успех: grade 3–5 для экзамена/дифзачёта, pass для зачёта. Отсутствие результата
не тождественно нулю. Современные аттестации и прежние записи зачётки
различаются; изменения опубликованных баллов не переписывают официальный итог.
Действующие правила — backend/academics/service.py, attestation.py и tests/test_academics.py.

## Электронные заявки V6

Раздел сохранён для ссылок из решений. Студент видит только собственные
обращения; Staff — только request_staff_scopes. Роль Staff сама по себе
не даёт доступа. Новое обращение submitted; владелец может отменить его
до обработки. Сотрудник переводит submitted → processing → approved/rejected
с комментарием. Терминальные состояния не возвращаются в работу.
Версия и append-only история меняются атомарно; конфликт — 409.
Повтор request_key с тем же нормализованным содержимым возвращает тот же объект,
изменённое содержимое — 409; новая операция требует нового ключа. Неизвестный
результат не даёт повода молча повторять отправку с новым ключом.
Квоты создания: 5/600 с и 20/86400 с на владельца, повторы не расходуют квоту,
отменённые заявки учитываются. В sessionStorage допустим только технический
маркер операции; текст и персональные данные не сохраняются. Введённый текст
сохраняется в памяти при допустимой повторной проверке того же аккаунта;
logout/смена пользователя его очищает. POST проверяет Origin/CSRF/JSON.
Одобрение обращения не равно выпуску справки: демонстрационные подпись и
передача — отдельные действия. Юридическая значимость не заявляется.
