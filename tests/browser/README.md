# Браузерная регрессия RC3.1 P1

Запуск из корня MGIMOv в PowerShell под Windows-пользователем, которому доступен DPAPI-файл Astra.
Нужны существующая `.venv` проекта, Node.js и установленный Google Chrome.
Для чистого клона или распакованного ZIP заранее подготовьте локальную синтетическую
SQLite совместимого сценария и парный DPAPI-файл. Разместите их в
`.tmp/astra-phase3-browser-20261113/` под именами `demo.sqlite3` и `demo.dpapi`.
DPAPI должен открываться под Windows-пользователем, запустившим тесты.
Оба файла хранятся локально и исключаются из Git и ZIP.

```powershell
npm.cmd --prefix tests/browser ci --ignore-scripts
npm.cmd --prefix tests/browser test
```

Тест использует пару `.tmp/astra-phase3-browser-20261113/demo.sqlite3` и `demo.dpapi`.
Он создаёт отдельную SQLite и запускает свой Uvicorn на свободном порту loopback.
При штатном завершении запуска тест останавливает этот процесс и удаляет копию.
Для входа Playwright нажимает кнопку в реальном Chrome. Пароли передаются из DPAPI
через закрытый канал процесса и вводятся вне записи trace. Скриншот маскирует форму входа.

Если тест видит применимое согласование на 4 при официальной оценке 2, он использует его.
В сохранённой контрольной базе итог уже исправлен на 4. В таком случае тест на своей
копии возвращает 2 через согласованное исправление, затем проводит пересмотр до 4.
Обе операции выполняются через браузер.

HTML-отчёт последнего запуска находится в `.tmp/playwright-p1/report/index.html`.
Скриншот при ошибке и trace при ошибке после входа находятся в каталоге сценария внутри
`.tmp/playwright-p1/results`. Новый запуск заменяет предыдущий отчёт и артефакты.
Trace может содержать тестовую сессию и синтетические учебные данные. Храните его локально.

## Комиссии S02 и S05

Только два сценария комиссий из корня проекта:

```powershell
npm.cmd --prefix tests/browser test -- commission.spec.js
```

У S02 сохранена завершённая комиссия по «Методам исследования». Подготовка на отдельной
копии удаляет строго ожидаемую последовательность «черновик → публикация → завершение»
и её побочные записи, восстанавливает защитные триггеры в той же транзакции и сохраняет
исходное назначение и первые две попытки. У S05 используется существующая комиссия
по «Демонстрационному праву» с черновиком оценки 2. Оба теста выставляют, публикуют
и завершают результат в Chrome. Тестовые часы сервера и браузера фиксируются по времени
сохранённого сценария, чтобы проверки не зависели от даты запуска.

T03 проверяется как участник комиссии, которому не поручено внесение результата.
D01 проверяется как сотрудник с правом назначения, у которого после третьей попытки
отсутствует форма нового назначения. Проверка запрета назначения выполняется через UI.

## Заключительные проверки RC3.1

```powershell
npm.cmd --prefix tests/browser test -- acceptance-access.spec.js acceptance-ui.spec.js
```

Пять тестов полномочий отправляют шесть прямых команд с настоящими сессиями и
CSRF. До и после каждого отказа сравнивается отпечаток данных одноразовой SQLite.
Проверки RU/EN и адаптивности используют отдельную копию на каждый тест.
Скриншоты на 390×844 и 1280×900 находятся в `.tmp/playwright-p1/results`.
Геометрические проверки охватывают выбранные элементы и ширину всей страницы.
