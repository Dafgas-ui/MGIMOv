# MGIMOv — локальный Release Candidate

RC содержит текущее рабочее дерево, включая необходимые новые файлы MVP, а не только
Git HEAD. Авторитетный состав и SHA-256 каждого файла — `RELEASE-MANIFEST.json`.
Исходный базовый HEAD не означает наличие исправлений в Git-коммите.

В архиве нет SQLite, DPAPI, паролей, .env, приватных ключей, .git и установленных
зависимостей. Не переносите в него рабочую базу. Все учебные данные вымышлены.
Это кандидат для независимой приёмки, не подтверждение публичной безопасности.

## Установка в чистой копии на Windows

Распаковать архив в отдельную папку. Открыть PowerShell в корне распакованного RC.
Нужны Python 3.13 и Node.js с поддержкой встроенного test runner.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --disable-pip-version-check -r requirements-test.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -q
node --test tests/*.test.js
```

Версии runtime и тестовых зависимостей закреплены в `constraints.txt` и
`requirements*.txt`. Для запуска без тестов достаточно `requirements.txt`.
Если доступен отдельно подготовленный wheelhouse, установку можно повторить без сети:

```powershell
.\.venv\Scripts\python.exe -m pip install --no-index --find-links C:\путь\к\rc-wheelhouse -r requirements-test.txt
```

## Новая тестовая SQLite и запуск

Следующая команда явно создаёт новую БД и применяет все миграции, включая 0006,
до наполнения синтетическими данными. Существующий файл не перезаписывается.
Пароли вводятся скрыто в вашем интерактивном терминале, 15–128 символов:

```powershell
.\.venv\Scripts\python.exe -B -m backend.commands.seed_mvp_demo --db .tmp/rc-demo.sqlite3 --confirm-demo
$env:MGIMOV_DB_PATH = '.tmp/rc-demo.sqlite3'
$env:MGIMOV_ORIGIN = 'http://127.0.0.1:8030'
.\.venv\Scripts\python.exe -B -m uvicorn backend.app:app --host 127.0.0.1 --port 8030 --no-proxy-headers
```

Открыть `http://127.0.0.1:8030`, остановить Ctrl+C. При занятом порте выбрать свободный
и одинаково изменить ORIGIN и `--port`. Не останавливать чужие процессы. Не использовать
порты 8000 и 8027 других проектов. Host/Origin/cookies/CSRF не отключать.

Аккаунты: `student_a`, `student_b`, `student_c`, `student_d`, `staff_demo`.
Каждому студенту назначены свои профиль, группа, учебные записи, обращения,
уведомления и демонстрационная справка. Staff работает только в своём факультете.
База и схема не создаются при обычном запуске приложения.

Вместо ручного ввода на Windows можно использовать `--credentials-file .tmp/rc-demo.dpapi`
при seed и затем `backend.commands.demo_credentials --file .tmp/rc-demo.dpapi` в
частном интерактивном терминале. Это НОВЫЕ случайные пароли для НОВОЙ среды;
DPAPI-файл не входит в релиз и не переносится между компьютерами.

## Проверка исправлений

- MVP-01: Staff без scope отправляет уведомление существующему недоступному и
  несуществующему студенту, редактирует недоступное и отсутствующее занятие.
  Во всех случаях одинаковые 404/JSON; нет изменений и ложных audit-записей.
- MVP-02: в очереди из 21+ обращений перейти на следующую страницу, открыть старую
  одобренную заявку на справку. В деталях нажать «Подписать демонстрационную справку»,
  затем «Передать справку студенту». Владелец получает документ; чужой студент — нет.
  Выпуск использует прежние backend-сервисы, scope и version/409.
- MVP-03: уведомления сортируются по `(created_at DESC,id DESC)`; кнопки «Старые
  уведомления» / «Новые уведомления» используют непрозрачный cursor. Прочтение не
  меняет порядок и сохраняет страницу; общий unread count обновляется. API принимает
  `cursor`, а не offset: `GET /api/v1/me/notifications?cursor=...`. Первый запрос без
  параметров сохраняет прежние `items`/`unread`, дополнительно возвращает `next_cursor`.

Справки и подписи исключительно демонстрационные и не имеют юридической силы.
После установки повторить Student → Staff → Student на новой SQLite. Подробные
команды и фактические результаты текущей сборки выдаются в отчёте стабилизации.

## RC2 Design: интерфейс конкурсного MVP

- Student R1: учебный день, расписание, зачётка, обращения, документы и уведомления.
- Staff R3: очередь с деталями, справки, студенты, расписание и история выбранного
  обращения. Фильтр очереди применяется к текущей странице.
- Schedule R2: недельный режим с семью днями и прокруткой внутри календаря на
  узком экране. Редактирование занятия использует штатное уведомление группы.
- Идентификаторы обращения и документа раздельные; связь по `request_id`.
  Миграции, прикладные API и серверная проверка прав остаются прежними.

Перед показом проверить SHA-256 ZIP и провести независимую приёмку именно этого
артефакта. Приёмка RC1 не распространяется на новый интерфейс.

## RC2-02: два исправления по дизайн-аудиту Luna

- «Настройки» доступны после подтверждения сессии Student или Staff.
  Анонимная ссылка `#settings` оставляет пользователя на экране входа.
  После входа открывается основной раздел роли. При сбое выхода кнопка
  «Повторить выход» доступна на экране входа.
- Для первого открытия и сброса используются Light и Emerald. Светлая тема
  задана уже в HTML. Сохранённые Light, Dark и System, палитры и свой цвет
  продолжают загружаться для своего аккаунта.

Для браузерной проверки запустите FastAPI на новой демобазе по инструкции
выше. В новом профиле браузера с тёмной системной темой откройте
`http://127.0.0.1:8030/#settings`. Проверьте светлый экран входа, затем
войдите как Student и Staff и откройте настройки вручную. Выберите Dark или
System, перейдите в другой раздел и обратно, обновите страницу, проверьте
сохранение выбора. Нажмите «Сбросить оформление» и проверьте Light и Emerald.
После выхода повторите прямой переход к настройкам.
