# Архитектура, утверждённая на V1

## Целевая система

Самостоятельный проект с отдельным Git, окружением, конфигурацией и SQLite.
Frontend HTML/CSS/ES modules и FastAPI работают с одного origin. Один экземпляр
сервера и постоянный локальный диск. Бизнес-данные хранятся на сервере.
localStorage не используется для персональных данных. Нет Telegram и старой
синхронизации полных JSON-снимков. Внешние системы университета не подключаются.

Целевые модули: профиль, групповое расписание, личная успеваемость, заявки,
уведомления. Frontend будет разделён на API-клиент, состояние сессии, страницы,
компоненты и независимые вычисления. Backend — маршруты, сервисные правила и SQL
по модулям; дополнительные абстрактные слои не обязательны.

## Целевые этапы (статус реализации уточнён ниже)

V3: Argon2id, серверные сессии, Secure/HttpOnly/SameSite cookies для HTTPS,
CSRF, два вымышленных студента и сотрудник. Публичная регистрация не нужна.
Студент читает свои профиль, оценки, заявки и уведомления, расписание своей группы.
Сотрудник получает операции по факультету: обработка заявок, публикации,
изменение расписания. Автоматического доступа к оценкам нет.

Реляционные сущности: users/sessions; профили; факультеты/программы/группы;
преподаватели/дисциплины/семестры/зачисления; серии и занятия с историей изменений;
оценки/результаты аттестаций; типы/заявки/история; объявления/уведомления.
Профиль получает факультет и программу через группу. Повторения разворачиваются
в занятия в пределах семестра. Время аудита UTC, учебный календарь Europe/Moscow.
Персональный SQL ограничивается владельцем; staff-операции — областью полномочий.
Изменения используют version и 409, история и уведомления записываются атомарно.

V4 — расписание; V5 — успеваемость; V6 — заявки; V7 — уведомления; V8 —
проверка MVP; V9 — согласованные улучшения и сдача. Тесты добавляются по этапам.
Первый HTTPS-стенд планируется после V3. Дополнительные ИИ-функции не выбраны.

## Реальный объём V2

backend/app.py: create_app(Settings), GET /api/health и явный список frontend assets.
backend/config.py: только MGIMOV_DB_PATH, путь ограничен этим проектом.
backend/db.py: существующая SQLite, foreign_keys, read-only чтение и BEGIN IMMEDIATE
для записи. Запуск приложения ничего не создаёт в базе.
backend/migrations: новая 0001_initial с технической меткой приложения и история.
backend/security/passwords.py: примитив Argon2id без маршрутов авторизации.
frontend: стартовая страница, клиент GET JSON, независимые функции дат, тёмная тема.

Исторически V2 health проверял целостность/схему и метку приложения. После V3
hardening public health стал лёгким; полная диагностика вынесена в локальную
команду. Пути и содержимое базы не публикуются (детали ниже).
Доступ к файловой системе через API отсутствует: опубликованы только перечисленные assets.

## Интерфейс

Тёмная тема, фиолетовый и мятный акценты, карточки. Системные шрифты, без логотипа
вуза и внешних CDN. На странице явно указано, что сервис неофициальный.
CSS меняет две колонки на одну на узком экране. Реальная мобильная QA ещё предстоит.

## Реальный объём V3

Backend: auth/service.py — вход, throttling, resolve/CSRF, отзыв; auth/http.py —
exact Host/Origin/transport, Fetch Metadata, bounded JSON; auth/routes.py — строгие
DTO и безопасные ошибки; profiles.py — owner-scoped SQL в read-транзакции.
Новая 0002_identity: users, sessions, auth_rate_limits, faculties, programs,
study_groups, student_profiles, staff_profiles. Профиль студента получает факультет,
программу и курс через группу. V2 SQL не изменялся, default working DB не мигрирована.
Создание users+профилей+справочников seed_demo выполняется одной транзакцией.

API prefix /api/v1: auth/csrf (GET), auth/login (POST), auth/me (GET),
me/profile (GET), auth/logout (POST). Нет выбора чужого user_id или повышения роли.
Staff получает только собственное служебное представление; faculty permissions,
редактор ролей, смена/восстановление пароля и учебные модули пока отсутствуют.
Перед их реализацией потребуются отзыв/ротация сессий при изменении credentials/прав.

Токены session и CSRF — secrets.token_urlsafe(32), в SQLite SHA-256; срок 8 часов,
выход отзывает строку, вход отзывает представленную прежнюю cookie и создаёт новую.
Active пользователя проверяется при каждом защищённом чтении. Logout resolve/CSRF
и revoke выполняются под одной write-транзакцией. Все SQL параметризованы.
Для login используется отдельный preauth CSRF cookie/header и exact Origin.

Frontend: API-клиент, независимый memory-only account-state и DOM adapter account.js.
Generation/AbortController скрывают старые данные и игнорируют поздние ответы.
X-Mgimov-User обозначает ожидаемый аккаунт, прав не выдаёт. BroadcastChannel
передаёт только сигнал invalidation; сервер повторно проверяет owner по cookie.
Скрытая вкладка/pagehide очищает представление; возврат, online и минутная проверка
в видимой вкладке проверяют сессию. Персональные данные в browser storage не пишутся.
После неуспешного logout данные скрыты, выход можно повторить. Отдельные вкладки
одного browser profile разделяют cookie; это не два независимых хранилища сессий.

Два HTTP-клиента в интеграционных тестах обеспечивают независимые студенческие сессии.
Для ручной проверки двух одновременных аккаунтов использовать разные профили браузера.
Браузерная QA V3 на 360 px остаётся неподтверждённой из-за недоступности браузерного runtime.

## V3 hardening (текущее уточнение)

auth/limits.py — атомарные source/pair budgets и bounded verification slots;
успешный вход возвращает только свой счётчик. Общей длительной блокировки логина
или приложения больше нет. Ошибки с одного источника всё ещё могут ограничить
клиентов за общим NAT; распределённую нагрузку решает периметр.
Logout делает дешёвый предварительный отказ, сохраняя повторную транзакционную проверку.
health.py — лёгкая read-only readiness; commands/diagnose.py сохраняет полную
проверку менеджера миграций. commands/cleanup_sessions.py — явная ограниченная очистка,
без удаления действующих сессий и без изменения TTL. Новых таблиц/миграций нет.
IdentityGuard ограничивает абсолютное время чтения body, не только размер.
Frontend сохраняет несданный пароль при фоновом poll и ручном refresh.
