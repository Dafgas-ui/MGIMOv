# Архитектура, утверждённая на V1

## Целевая система

Самостоятельный проект с отдельным Git, окружением, конфигурацией и SQLite.
Frontend HTML/CSS/ES modules и FastAPI работают с одного origin. Один экземпляр
сервера и постоянный локальный диск. Бизнес-данные хранятся на сервере.
localStorage не используется для персональных данных. Нет Telegram и старой
синхронизации полных JSON-снимков. Внешние системы университета не подключаются.

Целевые модули: профиль, групповое расписание, личная успеваемость, заявки,
уведомления. Frontend будет разделён на API-клиент, состояние сессии, страницы,
компоненты и независимые вычисления. Backend — маршруты, сервисные правила и SQL
по модулям; дополнительные абстрактные слои не обязательны.

## Последующие этапы: пока не реализовано

V3: Argon2id, серверные сессии, Secure/HttpOnly/SameSite cookies для HTTPS,
CSRF, два вымышленных студента и сотрудник. Публичная регистрация не нужна.
Студент читает свои профиль, оценки, заявки и уведомления, расписание своей группы.
Сотрудник получает операции по факультету: обработка заявок, публикации,
изменение расписания. Автоматического доступа к оценкам нет.

Реляционные сущности: users/sessions; профили; факультеты/программы/группы;
преподаватели/дисциплины/семестры/зачисления; серии и занятия с историей изменений;
оценки/результаты аттестаций; типы/заявки/история; объявления/уведомления.
Профиль получает факультет и программу через группу. Повторения разворачиваются
в занятия в пределах семестра. Время аудита UTC, учебный календарь Europe/Moscow.
Персональный SQL ограничивается владельцем; staff-операции — областью полномочий.
Изменения используют version и 409, история и уведомления записываются атомарно.

V4 — расписание; V5 — успеваемость; V6 — заявки; V7 — уведомления; V8 —
проверка MVP; V9 — согласованные улучшения и сдача. Тесты добавляются по этапам.
Первый HTTPS-стенд планируется после V3. Дополнительные ИИ-функции не выбраны.

## Реальный объём V2

backend/app.py: create_app(Settings), GET /api/health и явный список frontend assets.
backend/config.py: только MGIMOV_DB_PATH, путь ограничен этим проектом.
backend/db.py: существующая SQLite, foreign_keys, read-only чтение и BEGIN IMMEDIATE
для записи. Запуск приложения ничего не создаёт в базе.
backend/migrations: новая 0001_initial с технической меткой приложения и история.
backend/security/passwords.py: примитив Argon2id без маршрутов авторизации.
frontend: стартовая страница, клиент GET JSON, независимые функции дат, тёмная тема.

Health проверяет целостность/историю схемы и метку приложения, не публикует пути
или содержимое базы. Это readiness-проверка небольшого V2, не метрика нагрузки.
Перед ростом базы полную проверку integrity следует вынести из частого health.
Доступ к файловой системе через API отсутствует: опубликованы только перечисленные assets.

## Интерфейс

Тёмная тема, фиолетовый и мятный акценты, карточки. Системные шрифты, без логотипа
вуза и внешних CDN. На странице явно указано, что сервис неофициальный.
CSS меняет две колонки на одну на узком экране. Реальная мобильная QA ещё предстоит.
