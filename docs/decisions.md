- RC4.1 №7/26, решение пользователя 18.11.2026: обычный зачёт имеет
  фиксированную шкалу 0 → «не зачтено», 50 → «зачтено». Новое создание,
  фиксация плана и утверждение политики отклоняют другую шкалу. Исторические
  планы и официальные результаты автоматически не переписываются.
  Экзаменационную оценку выставляет преподаватель; БРС определяет условия
  допуска с базовым порогом 50 и действующими обязательными условиями плана.
  Дифзачёт использует утверждённую шкалу. Структура официальной БРС — 20/20/20/40.
  Прогноз не меняет зачётку, не публикует баллы и не является калькулятором №27.

- V1/V2: отдельное приложение и история Git вместо конкурсной ветки Dashboard.
- Сохраняем HTML/CSS/ES modules, FastAPI и SQLite; усложнение стека не требуется.
- Новая база содержит только техническую метку, а не перенесённые данные Dashboard.
- Миграции запускаются вручную. Startup и health не создают базу.
- Конфигурация разрешает только project-local SQLite, включая временные тестовые базы.
  Это защита от случайного выбора внешней базы, не песочница для недоверенного Python.
- Статические файлы перечислены явно: нет публикации корня проекта или каталогов данных.
- Старый script.js слишком связан с DOM, задачами и статистикой; его не копируем.
- Функции дат принимают явные аргументы. Они работают с календарными ключами;
  определение сегодняшнего дня в Europe/Moscow появится вместе с расписанием.
- Argon2id перенесён без генерации DUMMY_HASH при импорте: входа пока нет.
  Защиту от перечисления логинов и dummy verification необходимо вернуть в V3.
- Менеджер миграций использует новую SQL-схему. Общие возможности baseline сохранены
  внутри перенесённого кода, но не опубликованы в новом CLI.
- API-клиент V2 поддерживает только GET и локальные пути. Mutations/CSRF — V3.
- Независимое окружение фиксируется requirements/constraints, без npm-зависимостей.
- В HTTP-тесте Windows запускается базовый интерпретатор с site-packages новой .venv:
  завершение venv launcher не гарантировало закрытия дочернего процесса и лога.
- Git-коммит создаётся с техническим автором Codex, без изменения глобального Git config.
- До публикации проверить происхождение заимствованных фрагментов и лицензии зависимостей.
  Собственная лицензия проекта на V2 не назначается от имени пользователя.

## V3 — принятые решения реализации

- Разрешение: отдельное задание V3, без коммита, публикации и перехода к V4.
- Сохранены Argon2id/SQLite/миграции V2; новая 0002_identity, исходная 0001 не менялась.
- Публичная регистрация не нужна. Только явный интерактивный seed отдельной пустой
  демобазы; работа с default working DB запрещена командой seed.
- API соответствует V1 (/api/v1); нет публичного arbitrary profile endpoint.
- Login CSRF: bootstrap token в HttpOnly cookie и JSON для памяти клиента + header;
  logout CSRF: session-bound hash и cookie/header. Обе операции требуют exact Origin.
- Local HTTP ограничен loopback origin, HTTPS включает Secure/__Host cookies;
  origin задаётся явно через MGIMOV_ORIGIN. Не отключать проверки для публикации.
- Ответы персонального API no-store, без хешей/токенов/traceback. Некорректный Unicode
  обрабатывается общим 422. Лимиты login persistent, Argon2 semaphore сохраняется.
- Старые предупреждения health и Starlette/httpx не расширяют объём V3.
- В V3 не добавлены смена пароля, восстановление, редактирование ролей и глобальные
  права staff; при их добавлении отдельно связать операции с отзывом сессий.
- Однократный security_reviewer использован только для статического чтения;
  это не независимая динамическая приёмка Astra. Результаты тестов принадлежат Sol.

## V3 hardening — SEC-01…04

- Источник задания: пользователь передал выводы независимого аудита Astra Medium;
  полный исходный отчёт не найден в проекте и не объявляется прочитанным Sol.
- SEC-01: убраны global-100 и cross-source login-10 блокировки. Source/pair counters
  резервируются до Argon2 атомарно и проверяются повторно под BEGIN IMMEDIATE;
  успех возвращает свою резервацию, не стирая чужие ошибки. Pair 5/source 30 за
  60 секунд — не единственное изменение: область, refund и admission изменены.
- Для NAT разные логины имеют отдельные pair budgets; общая source-квота остаётся.
  Чужие попытки с другого адреса больше не ставят 900-секундный запрет владельцу.
  Ошибки за одним NAT всё ещё могут временно ограничить весь источник.
- IP rotation обходит локальный source budget как сетевую идентичность, но не
  процессный максимум 2 проверок и максимум 1 на логин. Это ограничение
  конкурентности, не полноценный распределённый rate limit. Нельзя заявлять,
  что распределённый перебор/DoS решён без периметра. 503 при занятых slots
  может затронуть легитимного пользователя; residual risk явно сохранён.
- SEC-02: повторные 429/невалидный logout/неверный CSRF отбрасываются без writer;
  правильный logout снова проверяет session+CSRF под writer. Lock wait новых
  login/logout операций 0.25 секунды с общим 503 при занятости вместо долгого ожидания.
- SEC-03: health сверяет метку и migration history + основные SELECT LIMIT 0,
  без полного integrity/schema replay. Контракт JSON/status 200/503 не изменён.
  Полная диагностика — локальная read-only command diagnose, не endpoint.
- SEC-04: identity body deadline 10 секунд абсолютный, 8192 байта;
  proxy/headers/connections остаются обязанностью будущего периметра.
- UI: минутный poll не опрашивает анонимную форму; publish не стирает черновик.
  Пароль очищается при явной отправке, успешной загрузке кабинета и pagehide.
- Сессии: явная bounded cleanup без scheduler, TTL сохранён. Миграции не менялись.
- Starlette/httpx не обновлялись. Коммит, публикация и V4 не выполнялись.
