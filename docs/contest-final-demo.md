## Подготовка отдельного экземпляра

Запускайте из приватного checkout с текущей версией генератора. На Windows
подготовка проверяет права пути и создаёт защищённую папку в `.tmp`. Не пытайтесь
исправлять ACL общей папки проекта; используйте приватную копию, описанную в
[README](../README.md#локальный-запуск-windows-11-на-порту-8030).

```powershell
Set-Location -LiteralPath 'C:\path\to\private\MGIMOv'
.\.venv\Scripts\python.exe -B -m backend.commands.seed_contest_final `
  --confirm-demo --anchor-date 2026-11-21
```

Дата-якорь конкурса — 21 ноября 2026 года (суббота); расписание также покрывает
22 ноября (воскресенье). Сроки двух работ приходятся на 23 и 24 ноября, а право
преподавателя действует семь дней от якорной даты. Для другого показа задайте
явную дату `--anchor-date YYYY-MM-DD`; не переводите системные часы.

Команда сначала строит SQLite в случайно названном staging-файле внутри новой
приватной папки `.tmp`, затем проверяет данные, миграционный статус,
`integrity_check` и `foreign_key_check`. Только после успеха файл атомарно
публикуется как `demo.sqlite3`; при ошибке staging удаляется, а готовый путь не
появляется. Существующий путь отклоняется и не перезаписывается. Отдельный `init`
перед ней не нужен. Вывод содержит
`DEMO_DB`, агрегат `DEMO_SUMMARY` и место зашифрованных учётных данных. В Windows
пароли хранятся в DPAPI-файле текущего пользователя; при необходимости показать
их делайте это только в приватной интерактивной консоли:

```powershell
.\.venv\Scripts\python.exe -B -m backend.commands.demo_credentials `
  --file '.tmp\contest-demo-<id>\credentials.dpapi'
```

Не копируйте DPAPI-файл, не включайте его в Git/ZIP и не записывайте раскрытые
пароли в логи, скриншоты или конкурсное видео. Каждый из 20 паролей создаётся
случайно и отличается от остальных. На POSIX CLI раскрывает значения только в
интерактивном терминале; Linux ACL-проверка для данного генератора отдельно
не подтверждена.

После подготовки:

```powershell
$env:MGIMOV_DB_PATH = Read-Host 'Путь DEMO_DB из вывода seed'
$env:MGIMOV_ORIGIN = 'http://127.0.0.1:8030'
.\.venv\Scripts\python.exe -B -m backend.commands.diagnose --db "$env:MGIMOV_DB_PATH"
.\.venv\Scripts\python.exe -B -m uvicorn backend.app:app `
  --host 127.0.0.1 --port 8030 --no-proxy-headers
```

В другом приватном терминале открыть `http://127.0.0.1:8030/`, проверить входы
и сценарии ниже, затем остановить только свой сервер `Ctrl+C`. Не передавать
демобазу как готовый артефакт и не использовать production-пароли.

## Помещения и расписание

Генератор добавляет пять вымышленных корпусов и 50 помещений с вместимостью
16–96 и несколькими комбинациями оборудования. Вместе с одним базовым учебным
помещением в файле всего 51 помещение. Вымышленные корпуса покрывают известный
график, закрытое воскресенье и неизвестный режим доступа; два временных и два
долгосрочных ограничения. Причины ограничений наружу не выдаются.

| Сценарий | Дата/пример |
|---|---|
| Два потока занимаются одновременно | 21 ноября, 09:00–10:00, A-01 и A-02 заняты |
| Отменённая пара освобождает аудиторию | 21 ноября, 10:00–11:00, A-03 |
| Перенесённая пара | 22 ноября, из A-06 11:00 в D-01 12:00 |
| Временное ограничение | A-09, 21 ноября 08:00–12:00 |
| Постоянное ограничение | A-10 |
| Неизвестные правила доступа | Все помещения корпуса C |
| Известные часы и закрытый день | B/E открыты в субботу и закрыты в воскресенье; A/D работают оба дня |
| Активный и отменённый экзамены | 23 ноября 14:00, E-01 занят, E-03 свободен после отмены |
| Другое активное назначение экзамена | 24 ноября 14:00, A-04 занята |

Расписание строится через существующий сервис изменений расписания. Отменённые
занятия/испытания не выдаются за занятые. Поиск помещений остаётся read-only;
доступность не является бронированием или гарантией доступа.

## Автоматические проверки

В изолированной среде с установленными зависимостями:

```powershell
python -B -m unittest -v tests.test_contest_final_demo
```

Набор проверяет всю миграционную цепочку текущего checkout (включая
0026 QR), целостность/FK, все 20 активных
учётных записей и проверку хешей предоставленных seed паролей; а также границы
49/50/51, отделение прогноза от официального результата, задолженность,
Coursework, датированную историю посещаемости, роли Staff и сценарии поиска
помещений. SQL/сервисы работают на временной синтетической SQLite в `.tmp`.

Полный прогон HTTP через Uvicorn и браузер необходим отдельно непосредственно
перед конкурсным показом. На проверочном Windows-окружении Luna TCP bind на
loopback прошёл, но TCP connect завершился `WinError 10013`; health, входы и
браузерный показ поэтому остались NOT VERIFIED. Тесты сервисной логики не заменяют
эти проверки. Chrome/мобильные размеры этой генерацией не проверялись.

## Ограничения и дальнейшие действия

- Текущий генератор применяет миграции, которые есть в текущем checkout. После
  QR-посещаемости заново запустить его на новой ветке и проверить актуальную схему.
- База создаётся только для локальной репетиции; финальная SQLite, ZIP, релиз и
  публичные доступы не создаются этим этапом.
- UI не изменён. Проверка через сервисы и SQL не подтверждает Student/Staff UX,
  мобильное поведение, Chrome, вход по паролям через браузер или читаемость RU/EN.
- Вложения соответствуют реализованному пределу TXT/MD; PDF/DOCX не заявляются.
- Аккаунт A01 — Staff, но не получает дополнительных учебных полномочий по роли.
- Linux-права, браузерный конкурсный прогон и независимая приёмка Astra не выполнены.
- Официальное ТЗ конкурса и соответствие его критериям не подтверждены.
