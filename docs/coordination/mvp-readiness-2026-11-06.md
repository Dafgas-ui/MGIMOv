## Реализация и решения

- [0006_mvp.sql](../../backend/migrations/0006_mvp.sql): `notifications`, `demo_documents`,
  `staff_audit`, `registration_invitations`. Старые миграции не менялись. Запуск
  приложения не применяет миграции и не создаёт БД.
- [deanery/routes.py](../../backend/deanery/routes.py), `install_deanery`: строгие DTO,
  запрет дополнительных параметров, существующая защита Host/Origin/CSRF.
- [deanery/service.py](../../backend/deanery/service.py): `actor`, `group_scope`,
  `document_scope` проверяют живую сессию и область доступа. `edit_lesson` проверяет
  версию и пересечения группы/аудитории/преподавателя. `mutate` повторяет проверку
  полномочий внутри write-транзакции. `sign_document` требует одобренную заявку на
  справку, сохраняет неизменяемое содержимое и SHA-256; `deliver` открывает доступ
  владельцу и создаёт уведомление. SHA-256 здесь контроль содержимого, не ЭП.
- [events.py](../../backend/events.py), `notify`, `notify_group`, `audit` вызываются в
  той же транзакции, что изменение. [requests/service.py](../../backend/requests/service.py),
  `create_in_transaction` и `transition_in_transaction` добавляют события существующих
  заявок. Отмена студентом остаётся в истории обращения, Staff-операции — в журнале.
- [registration.py](../../backend/auth/registration.py), `register`: одноразовое
  приглашение на группу, хеш приглашения в SQLite, Argon2id, существующее ограничение
  попыток до хеширования, атомарное потребление приглашения. Роль всегда Student,
  группа берётся из приглашения; автоматического входа нет. Это ограниченная
  регистрация, а не свободное создание аккаунтов с произвольными полномочиями.
- [seed_mvp_demo.py](../../backend/commands/seed_mvp_demo.py), `seed`: использует существующие
  seed-механизмы V3–V6, добавляет C/D и личные документы/события. При повторном запуске
  с существующим файлом отказывает без изменений; повторное развёртывание выполняется
  с новым именем БД. Частично созданную среду нельзя автоматически перезаписывать.
- [demo_credentials.py](../../backend/commands/demo_credentials.py): случайные пароли
  доступны через Windows DPAPI текущему пользователю Windows; альтернативно seed

- [mvp.js](../../frontend/js/mvp.js), `render`, `buildStaffForms`, `showDocument`:
  новые разделы встроены в [index.html](../../frontend/index.html), отдельного `/mvp` нет.
  Ответы сервера выводятся текстом; документ скачивается как текстовый Blob.

- В [account.js](../../frontend/js/account.js) добавлены только интеграция жизненного

## API

Все маршруты ниже имеют префикс `/api/v1`, защищённые ответы — `no-store`.
Изменения требуют Origin, session-bound CSRF и живые серверные полномочия.

| Метод и путь | Назначение |
|---|---|
| POST `/auth/register` | Регистрация по приглашению; login CSRF bootstrap |
| GET `/me/notifications` | Последние 100 собственных уведомлений и общий unread count |
| POST `/me/notifications/{id}/read` | Отметка собственного уведомления |
| GET `/me/documents`, `/me/documents/{id}` | Собственные переданные справки; у Staff — доступ в факультетной области |
| GET `/staff/students`, `/staff/catalogue` | Студенты разрешённых факультетов, группы и учебные справочники |
| GET/POST `/staff/lessons` | Последние 200 доступных занятий / создание |
| POST `/staff/lessons/{id}` | Изменение date/time/teacher/room/status с version/reason |
| POST `/staff/requests/{id}/reply` | Ответ с version, историей и уведомлением |
| POST `/staff/requests/{id}/sign` | Демонстрационное подписание одобренной справки |
| GET `/staff/documents` | Список справок в факультетной области |
| POST `/staff/documents/{id}/deliver` | Передача справки владельцу |
| POST `/staff/notifications` | Уведомление выбранному студенту в разрешённом факультете |

Статусы и решения использует прежний `/staff/requests/{id}/decision`.
Для подписания заявки за пределами первой страницы списка Staff может работать
через существующую пагинированную очередь/API; новый обзор показывает первые
20 обращений. Это ограничение больших наборов, не ограничение текущей демосреды.

## Безопасность и ограничения

Проверка по направлениям deanery-security-review — проверка разработчика, не новый
независимый PASS Astra. Подтверждённых обходов на проверенной поверхности не найдено;
это не доказательство полной безопасности.

| Направление | Основание / граница |
|---|---|
| Авторизация и сессии | Существующие resolve/CSRF/Host/Origin, старые регрессии; новые actor и повторный writer-check |
| Пароли и учётные данные | Штатный Argon2id, SecretStr, ограничение регистраций, DPAPI; нет почты/recovery |
| Изоляция студентов | Четыре независимые API-сессии, собственные списки, чужие requests/documents/notifications запрещены |
| Подмена ID / IDOR | Чужие URL ID отклоняются; owner query не принимается; UUID не используется как разрешение |
| Полномочия | Student → Staff 403; отзыв faculty scope → недоступны список/изменение/ответ/передача |
| CSRF, cookies и API | Существующие Origin/Host/cookies, session CSRF, строгие DTO, SQL-параметры; GET не изменяет бизнес-состояние |
| Утечки | Новых personal localStorage/sessionStorage нет; текстовые DOM узлы, no-store; SecretStr, DPAPI/SQLite/logs вне Git |
| Регрессии | 101 Python / 61 JS, включая старые AUD/UX/appearance и реальные HTTP; SQLite FK/immutable/audit/rollback и конкуренция |

Остались ограничения: новые обзоры ограничены 100 уведомлениями, 200 студентами и
занятиями, первая страница действий над справками — 20 обращений. Для больших
наборов нужна полноценная навигация; это не проверка масштабируемости. Нет фоновой
доставки/почты, PDF и реальной ЭП. Смена дисциплины/группы/типа существующего занятия
не поддерживается редактором: доступны создание и согласованные перенос/отмена/
преподаватель/аудитория. Подтверждение результата после сетевой потери — ручное
обновление, административные POST автоматически не повторяются.

**Не проверены:** публичный сервер, HTTPS/reverse-proxy/cookies за инфраструктурой,
нагрузка/DoS, реальные Chrome/Edge на телефонах, полная клавиатурная доступность и
screen reader, все визуальные состояния/темы/устройства, естественное переключение
браузерных вкладок. Visibility-сценарии проверены автоматическими DOM/state тестами;
они не объявляются реальным переключением вкладок. Известное предупреждение
Starlette/httpx остаётся; зависимости без отдельного задания не заменялись.
